Vital Lab

Neutral training simulator with one generic demonstration casualty and eleven illustrative observation items. Course handouts, real patient information, private session records and credentials are not included.

Instructor workflow

  • Setup contains patient/case preparation and Field → Truck → Clinic display assignments.
  • Run shows phases on the left and vital controls on the right. The sticky clock, pause and Mark Intervention controls remain visible.
  • Tools holds student display, ventilator, display setup, logs/CSV, reports and panel arrangement.
  • Camera picks GoPro, Patient, Clinic 1 or Clinic 2. Every camera is unconfigured until a supported feed is added.
  • VIP View selects the content for VIP Screens 1–3 independently, or all screens together. VIP browser links remain read-only.

Local network

Run python host.py or the Windows launcher. Keep the host and instructor browser running. Open the printed observer links on monitoring-room devices. Each browser chooses its VIP channel; the instructor chooses its content. Closing an observer does not stop local simulation.

Static hosting supports the instructor and student popup. The local host is required for native display inventory and remote VIP selection. This is not connected to the separate documentation app merely by sharing a repository.

Displays and cameras

Connect compatible receivers in Windows first and use Extend. The browser can select connected screens with permission; it cannot pair an unconnected receiver. Fullscreen can need a click or F11. No fully automatic receiver power-on workflow or camera compatibility is claimed.

Recovery and reports

Reusable cases, instructor logs, observations and clinical-document backups remain separate. Export before moving files or clearing browser data. All-bed recovery is explicit and paused. Use simulated data only. Student documentation or checklist marks do not establish clinical outcomes.
